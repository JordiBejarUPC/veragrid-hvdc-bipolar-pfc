ANDES VERSUS VERAGRID RMS DYNAMIC BENCHMARK [rotor_speed_state_step]
==============================================================================

SCOPE AND FAIRNESS
The five validated networks use the same fixed-step Backward Euler method, 1 ms integration step, 2.0 s horizon and 1e-6 nonlinear tolerance. Both programs start from the unperturbed equilibrium and apply the same additive 1e-4 pu step to the same physical rotor-speed state at t=0.2 s.
On IEEE39 and WECC179, ANDES attempted a floating-point zero-length trailing step after storing t=2.0 s. Those runs are accepted only because the script verifies that the full requested 2,001-point grid is present; a genuinely early termination remains a hard failure. No adaptive step reduction is accepted.
Both programs solve power flow twice. The first cold run is retained only as a warm-up diagnostic; the second warm solve initializes RMS and is the only power-flow time included in the analyzed total. Result export is excluded.
Times are single wall-clock observations, not a statistical performance study. They explain the present runs but should be repeated before publishing claims.

WHAT EACH TIMING PHASE CONTAINS
Case/model build and pre-PF setup: ANDES parses the case and creates model arrays, addresses, sparse patterns and references; VeraGrid constructs the MultiCircuit, assigns every RMS template and wires symbolic variables.
Cold power flow: first solve and compilation/warm-up effects. It is excluded.
Warm power flow: second Newton solve. Its result is authoritative and included.
Dynamic initialization and symbolic-to-numeric: ANDES TDS.init versus VeraGrid RmsProblemDae construction, explicit dynamic initialization, residual/Jacobian compilation and solver-array allocation.
RMS integration: all 2,000 implicit Backward Euler steps. Each step evaluates the DAE, refreshes the honest Jacobian, solves the Newton linear system and checks the common tolerance.
Analyzed total: build/setup + warm power flow + dynamic preparation + integration. Cold power flow and CSV/figure export are not included.

TECHNICAL CONCLUSIONS
1. The models are locally equivalent in the selected linearization branch. The separately validated small-signal state matrices have relative errors from about 1.7e-10 to 6.0e-7, and their eigenvalues agree correspondingly. A broad equation or network-topology mismatch would not produce that result. This does not prove global nonlinear equivalence when a limiter changes branch.
2. State inventories are not textually identical. ANDES retains several BusFreq, zero-time-constant and limiter auxiliary states that VeraGrid folds into algebraic equations. Comparisons therefore use every common physical state, while explicitly reporting ANDES-only implementation states.
3. IEEE14 TGOV1 is now nonlinearly equivalent for the tested lower-limit transition: the previous 3.741e-4 governor-state mismatch is 7.61e-10. Its remaining 1.17e-4 residue is localized in zero-TA ESST3A LAW2 states. In WECC179, the VeraGrid IEEEG1 model still omits the ANDES rate and anti-windup branches by design, so that benchmark model is not globally equivalent outside its documented interior regime.
4. ANDES dominates VeraGrid dynamic preparation because it loads generated numerical model calls, while VeraGrid builds and compiles the composed symbolic DAE per run.
5. Over the two-second event horizon, VeraGrid wins IEEE14 integration while ANDES wins Kundur, IEEE39, NPCC140 and WECC179. The advantage is most pronounced for IEEE14 in VeraGrid and for IEEE39/NPCC140 in ANDES. The cost depends on total DAE dimension, Jacobian sparsity/fill-in, nonlinear iterations and factorization reuse, not only on the number of buses.
6. In these event measurements, ANDES wins the second warm power flow in three cases and VeraGrid in two. Warm-PF times are tiny compared with integration and show normal run-to-run noise; neither tool reads a pre-solved operating point for the measured warm solve.

WECC179
-------
The dominant mismatch is localized at LAW2_y ESST3A 26 and the IEEEG1-17 limiter chain. VeraGrid's IEEEG1 template explicitly implements the normal interior-limiter regime, whereas ANDES includes valve-rate limiting and an anti-windup valve-position integrator. The initial 3.575e-4 IEEEG1-17 offset excites ESST3A-26, whose error then decays. The validated 6e-7 relative state-matrix error rules out a network-wide machine-equation mismatch but does not establish equivalence of the nonlinear limiter branches.
